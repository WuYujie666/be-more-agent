树莓派 Agent 三方案对比（2026-10-22）

结论
当前功能推荐 native（现有 OpenAI SDK + 共享结构化决定/执行层），默认已设为 native。
LangChain 和 Pydantic AI 均能在这台 8GB 树莓派运行，资源不是障碍。
本次没有证据证明框架提高了模型意图识别准确率。当前工作流较短，统一执行层已
负责参数校验、权限、状态修改、结果确认和回退；框架增加的能力暂时不足以抵消
额外依赖和接口维护。适配器独立保留，后续增加复杂流程时可以重新选择。
这不是宣称原生方案云端响应一定更快；样本不足以支持这个结论。

最终实现与公平性
最终版本 structured-decision-v1：模型必须给出 chat / clarify / actions 决定；
actions 不允许附带成功回复。程序验证后执行，成功确认由真实工具回执生成。
搜索先单独执行，然后把真实 ID 和结果给模型；修改/删除仍经过所有权检查。
三个方案使用相同模型、业务提示词、数据、工具和执行层；适配器生成的 JSON
schema、消息包装和 token 数不同，不是逐字相同的请求。
native：SDK 强制调用 turn_decision；LangChain：with_structured_output；
Pydantic AI：Agent 的类型化输出。最终比较的是同一结构化决策工作流的三种
实现；不是 LangGraph 持久化状态图、完整生态功能或任意 Agent 工作负载比较。

离线：每方案新进程、11用例重复5次，热态普通聊天取后4次中位数；本地HTTP模拟
模型，不含真实推理及音频。内存为 /proc/self/statm，按本机实际16KiB页换算；
不是整个GUI/ASR/TTS/向量库进程内存，也不是框架安装大小。双设置时间存在系统
调度噪声，不能据几毫秒倒推普遍优劣。
真实模型：每用例每方案只做1次，11个用例为聊天、长期偏好、临时播放设置、
明天计划、住址纠错、选择遗忘、歧义追问、当前会话遗忘、遗忘改写、否定遗忘、
假设性提问。通过条件检查实际状态；框架异常直接失败，禁用本地回退掩盖错误。
“澄清”还检查问号，属于粗检查；不能据这些有限用例宣称语义完全正确。
语音：25.65秒 input_test_data.wav → SenseVoice → 各适配器 → 正式Sherpa合成器；
顺序 native/LC/Pyd，再反序，每方案2次。无麦克风/VAD/GUI，未测扬声器物理起音。
回复文本、首段长度和网络不同，因此不能依据两次语音结果排出框架速度名次。

结构化校验的代价
现在完整决定校验后才把回复交给TTS，普通聊天也不再逐token提前朗读。
原来的TTS句子切分与合成/播放流水线保留。历史 streaming 协议的首段范围为
native 2.14–3.16s、LC 2.34–2.76s、Pyd 2.76–3.24s（见旧 summary.json）。
这些不是固定回复的严格A/B，不能精确归因延迟差值。当前测量已包含校验代价。
日志改为“首段文本就绪”，避免把完整决定延迟误称为底层首token。

已验证功能
- 当前北京时间进入模型与记忆抽取请求；计划日期与记录时间分开。
- Mem0普通记录可搜索、纠错、选择删除；未知ID/其他用户记录不可修改。
- 明确“以后/默认”的偏好和日期计划暂存到会话结束统一写入，重启后可加载。
- 计划日期过去1至7天，在后续开场关心一次；不推断已经完成，不是定时闹钟。
- 本次助眠音量/时长可修改；当前只支持白噪音和轻音乐。
- 云端异常回退本地Qwen文字回复；实际注入云端超时后本地回复成功，14.22秒，
  未执行工具。下一轮仍先云端。实际本地回退样例见 local-fallback-decision.json。
- 29项离线单元回归、15项真实Mem0存储/重启/遗忘检查、32项TTS分段检查通过，
  LLM请求契约检查与 pip check 通过。
- 先前25秒音频完整写入/新进程回忆/清空检查12/12，见 memory_audio_results.json；
  该份结果来自先前LangChain流式版本，不能冒充最终协议的完整端到端复测。
  最终协议另有6次真实ASR→模型→TTS和15项共享存储检查。

遗忘失败、修正与剩余边界
最初三个自动工具调用方案都出现“口头答应但未执行”。后来加的固定句式 preflight
仅绕过了模型，不能证明模型调用可靠；现已删除，旧 live-*-recheck.json 不作为
最终语义成功证据。删除补丁后的 live-*-no-shortcut.json 保留了真实失败：
原句三者都漏执行；改写仅LC这一次执行。随后改成当前强制结构化决定与回执确认。
当前33个真实用例状态通过，只能证明这组小样本。模型仍可能误解请求或把操作
错分为聊天；chat回复仍是生成文字，例如LC否定遗忘用例出现“记在心里了”，
不能将其等同于完成了永久写入。结构校验并不证明语义正确，后续应扩大自然表述
测试，并以实际状态持续验收，不能用另一套固定关键词代替。

本次未声称完成的产品能力
- forget_recent 清除本次尚未保存的整段上下文，不支持精确抹除其中某一句。
  模型应对只删除局部且范围不清楚的请求先澄清。
- 纠错/选择删除也清空当前上下文与摘要，以防内容被结束时重新提取；其他长期
  记录保留。一条记录可包含多个事实，目标范围仍需正确识别。
- 管理型偏好/计划的修改采用删除后重新登记，避免文本和metadata值不一致。
- 偏好/计划未结束前是内存暂存，异常断电可能丢失。
- 音量只调整助眠播放，不调整TTS或系统音量。播放过程中主循环不监听语音，
  所以本次没有实现播放中语音调音量/打断。
- 本地Qwen降级模式不开放修改工具；无法完成云端未做的操作，不能声称已完成。
- 没有进行完整GUI、现场麦克风/VAD或多用户隔离部署验收。

失败实现清理
旧自动工具调用循环已替换，固定句式 preflight 已删除；保留失败结果及说明。
旧模拟测试曾因代理访问localhost失败、误触发Qwen而污染测量，已隔离localhost、
禁用基准回退并重测。当前模拟Pydantic搜索最初也因测试服务未处理合并system消息
失败，修正模拟服务后完整165项重测通过；smoke结果保留供审计。
